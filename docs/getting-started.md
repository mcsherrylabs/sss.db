# Getting Started with sss.db

This guide will take you from zero to your first working sss.db application in about 30 minutes. By the end, you'll understand how to:

- Set up sss.db in your Scala project
- Configure a database connection
- Perform CRUD operations
- Compose operations in transactions
- Handle errors properly

## Prerequisites

Before starting, make sure you have:

- **Scala 2.13** installed
- **sbt 1.x** (Scala build tool)
- **Java 11 or higher**
- **A database** (we'll use HSQLDB for this tutorial, but sss.db works with any JDBC-compatible database)
- **Basic Scala knowledge** (familiarity with for-comprehensions, case classes, and pattern matching)

## Step 1: Installation

### Add sss.db Dependency

Add sss.db to your `build.sbt`:

```scala
name := "my-sss-db-app"

version := "0.1.0"

scalaVersion := "2.13.10"

libraryDependencies ++= Seq(
  "com.mcsherrylabs" %% "sss-db" % "0.9.57",
  "org.hsqldb" % "hsqldb" % "2.6.1"  // For this tutorial
)
```

### Reload sbt

```bash
sbt reload
sbt compile
```

This will download sss.db and its dependencies (including HikariCP for connection pooling).

## Step 2: Database Setup

For this tutorial, we'll use HSQLDB (a pure Java SQL database) that runs in-memory. This is perfect for development and testing.

### Create Database Configuration

Create `src/main/resources/application.conf`:

```hocon
database {
  datasource {
    # HSQLDB driver (in-memory database for development)
    driver = "org.hsqldb.jdbc.JDBCDriver"
    connection = "jdbc:hsqldb:file:./data/myapp"  # File-based database
    user = "SA"
    pass = ""

    # Connection pool settings
    maxPoolSize = 10                    # Max concurrent connections
    connectionTimeout = 5000            # Wait 5s for connection

    # Performance optimizations
    cachePrepStmts = true               # Cache prepared statements
    prepStmtCacheSize = 250
    prepStmtCacheSqlLimit = 2048
  }

  # View metadata cache size (increase for many distinct queries)
  viewCachesSize = 100

  # Register JVM shutdown hook to close connections cleanly
  useShutdownHook = true

  # Release blob memory immediately after extraction (set true for large blobs)
  freeBlobsEarly = false

  # SQL to run on database startup (useful for creating tables)
  createSql = [
    """CREATE TABLE IF NOT EXISTS users (
         id BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1, INCREMENT BY 1),
         name VARCHAR(256),
         email VARCHAR(256),
         age INTEGER,
         active BOOLEAN,
         created_at BIGINT,
         PRIMARY KEY(id)
       )""",

    """CREATE TABLE IF NOT EXISTS posts (
         id BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1, INCREMENT BY 1),
         user_id BIGINT,
         title VARCHAR(512),
         content LONGVARCHAR,
         published BOOLEAN,
         PRIMARY KEY(id)
       )"""
  ]
}
```

**Configuration explained:**
- `datasource.driver`: The JDBC driver class for your database
- `datasource.connection`: JDBC connection string (file-based HSQLDB in this example)
- `datasource.maxPoolSize`: How many concurrent database connections to allow
- `createSql`: SQL statements to run when database initializes (creates tables if they don't exist)

### Alternative: PostgreSQL Configuration

For production with PostgreSQL:

```hocon
database {
  datasource {
    driver = "org.postgresql.Driver"
    connection = "jdbc:postgresql://localhost:5432/myapp"
    user = "myapp_user"
    pass = "secure_password"
    maxPoolSize = 20
  }

  viewCachesSize = 100
  useShutdownHook = false  # Let container manage lifecycle
}
```

⚠️ **Security Warning**: Never commit credentials to version control! Use environment variables:

```hocon
database {
  datasource {
    driver = "org.postgresql.Driver"
    connection = ${DATABASE_URL}      # From environment
    user = ${DATABASE_USER}           # From environment
    pass = ${DATABASE_PASSWORD}       # From environment
  }
}
```

## Step 3: First Connection

### Create Your First Scala Application

Create `src/main/scala/example/Main.scala`:

```scala
package example

import sss.db._
import scala.concurrent.ExecutionContext.Implicits.global
import scala.util.{Success, Failure}

object Main extends App {
  // Create a synchronous run context for blocking execution
  implicit val sync = new SyncRunContext(global)

  // Initialize database (loads "database" config from application.conf)
  val db = Db("database")

  // Get a handle to the users table
  val userTable = db.table("users")

  println("✓ Connected to database successfully!")
  println(s"✓ Table: ${userTable.tableName}")

  // Always shutdown cleanly
  db.shutdown.runSyncAndGet
  println("✓ Database connection closed")
}
```

### Run It

```bash
sbt run
```

You should see:
```
✓ Connected to database successfully!
✓ Table: users
✓ Database connection closed
```

**What just happened?**
1. We created a `SyncRunContext` - this tells sss.db to execute operations synchronously (blocking)
2. We initialized a `Db` instance from our config
3. We got a `Table` handle for the "users" table
4. We cleanly shut down the database connection

## Step 4: CRUD Operations

Now let's perform Create, Read, Update, and Delete operations.

### Insert (Create)

```scala
package example

import sss.db._
import scala.concurrent.ExecutionContext.Implicits.global
import scala.util.{Success, Failure}
import java.util.Date

object CrudExample extends App {
  implicit val sync = new SyncRunContext(global)
  val db = Db("database")
  val userTable = db.table("users")

  // Insert a new user
  val insertResult = userTable.persist(Map(
    "name" -> "Alice",
    "email" -> "alice@example.com",
    "age" -> 30,
    "active" -> true,
    "created_at" -> new Date().getTime
  )).runSync

  insertResult match {
    case Success(row) =>
      println(s"✓ Created user with id: ${row.id}")
      println(s"  Name: ${row.string("name")}")
      println(s"  Email: ${row.string("email")}")
      println(s"  Age: ${row.int("age")}")

    case Failure(e) =>
      println(s"✗ Insert failed: ${e.getMessage}")
  }

  db.shutdown.runSyncAndGet
}
```

**Key points:**
- `persist(Map(...))` inserts or updates a row
- `.runSync` executes the operation and returns `Try[T]`
- `row.id` gets the auto-generated ID
- `row.string("name")`, `row.int("age")` are type-safe accessors

### Query (Read)

```scala
// Find a specific user by email using prepared statements
val findResult = userTable.find(
  where(ps"email = ${"alice@example.com"}")
).runSync

findResult match {
  case Success(Some(row)) =>
    println(s"✓ Found user: ${row.string("name")}")

  case Success(None) =>
    println("✗ User not found")

  case Failure(e) =>
    println(s"✗ Query failed: ${e.getMessage}")
}

// Get multiple users (filter)
val activeUsersResult = userTable.filter(
  where(ps"active = ${true}")
  limit 10
).runSync

activeUsersResult match {
  case Success(users) =>
    println(s"✓ Found ${users.length} active users:")
    users.foreach { user =>
      println(s"  - ${user.string("name")} (${user.string("email")})")
    }

  case Failure(e) =>
    println(s"✗ Filter failed: ${e.getMessage}")
}
```

**Key points:**
- `ps""` interpolator creates prepared statements (prevents SQL injection)
- `find()` returns `Option[Row]` (single result)
- `filter()` returns `Seq[Row]` (multiple results)
- `where()` builds WHERE clauses with method chaining

### Update

```scala
// Update a user's age
val updateResult = userTable.update(
  Map("age" -> 31),
  where(ps"email = ${"alice@example.com"}")
).runSync

updateResult match {
  case Success(count) =>
    println(s"✓ Updated $count row(s)")

  case Failure(e) =>
    println(s"✗ Update failed: ${e.getMessage}")
}
```

### Delete

```scala
// Delete inactive users
val deleteResult = userTable.delete(
  where(ps"active = ${false}")
).runSync

deleteResult match {
  case Success(count) =>
    println(s"✓ Deleted $count row(s)")

  case Failure(e) =>
    println(s"✗ Delete failed: ${e.getMessage}")
}
```

## Step 5: Your First Transaction

The real power of sss.db comes from composing multiple operations in a single transaction using for-comprehensions.

### Transaction Example: Create User and Post

```scala
package example

import sss.db._
import scala.concurrent.ExecutionContext.Implicits.global
import scala.util.{Success, Failure}
import java.util.Date

object TransactionExample extends App {
  implicit val sync = new SyncRunContext(global)
  val db = Db("database")

  val userTable = db.table("users")
  val postTable = db.table("posts")

  // Compose multiple operations in a single transaction
  val transaction = for {
    // Step 1: Create a user
    user <- userTable.persist(Map(
      "name" -> "Bob",
      "email" -> "bob@example.com",
      "age" -> 25,
      "active" -> true,
      "created_at" -> new Date().getTime
    ))

    // Step 2: Create a post for that user
    post <- postTable.persist(Map(
      "user_id" -> user.id,              // Reference the user we just created
      "title" -> "My First Post",
      "content" -> "Hello from sss.db!",
      "published" -> true
    ))

    // Step 3: Update user to mark them as having posts
    _ <- userTable.update(
      Map("age" -> 26),  // Maybe they had a birthday!
      where(ps"id = ${user.id}")
    )

  } yield (user, post)

  // Execute the transaction
  transaction.runSync match {
    case Success((user, post)) =>
      println("✓ Transaction completed successfully!")
      println(s"  User: ${user.string("name")} (id: ${user.id})")
      println(s"  Post: ${post.string("title")} (id: ${post.id})")

    case Failure(e) =>
      println(s"✗ Transaction failed (all changes rolled back): ${e.getMessage}")
      // All operations in the for-comprehension are rolled back
  }

  db.shutdown.runSyncAndGet
}
```

**What happened?**
1. We composed three database operations using a for-comprehension
2. All three operations execute in a **single transaction**
3. If any operation fails, **all changes are rolled back** automatically
4. Connections are acquired and released automatically
5. The result is type-safe (`(Row, Row)`)

**Transaction guarantees:**
- ✅ **Atomicity**: All operations succeed or all fail (no partial updates)
- ✅ **Isolation**: Other transactions can't see intermediate state
- ✅ **Automatic rollback**: If any operation throws an exception, everything rolls back
- ✅ **Resource cleanup**: Connections are always returned to the pool

## Step 6: Error Handling

sss.db has a structured exception hierarchy for proper error handling:

```scala
import sss.db._
import scala.util.{Success, Failure}

val transaction = for {
  user <- userTable.persist(Map("name" -> "Charlie", "email" -> "charlie@example.com"))
  // ... more operations
} yield user

transaction.runSync match {
  case Success(user) =>
    println(s"✓ Success: ${user.id}")

  case Failure(e: DbOptimisticLockingException) =>
    // Another transaction modified the row (version conflict)
    println("⚠ Version conflict - retry with fresh data")
    // Implement retry logic with exponential backoff

  case Failure(e: DbException) =>
    // Recoverable database errors (constraint violations, deadlocks, timeouts)
    println(s"⚠ Database error: ${e.getMessage}")
    // Log and possibly retry

  case Failure(e) =>
    // Unrecoverable errors (configuration problems, schema issues)
    println(s"✗ Fatal error: ${e.getMessage}")
    throw e  // Propagate
}
```

**Exception types:**
- `DbOptimisticLockingException`: Version conflict (another transaction modified the row)
- `DbException`: Recoverable errors (constraints, deadlocks, timeouts)
- Other exceptions: Unrecoverable errors (config, schema, network)

## Step 7: Query DSL Features

### WHERE Clauses with Method Chaining

```scala
import sss.db._

// Find users with complex criteria
val users = userTable.filter(
  where(ps"age > ${25}")
  and(ps"active = ${true}")
  orderBy OrderDesc("created_at")
  limit 10
).runSyncAndGet

// IN clause for multiple values
val userIds = List(1L, 2L, 3L, 4L, 5L)
val selectedUsers = userTable.filter(
  where("id").in(userIds)
).runSyncAndGet

// NOT IN clause
val excludedUsers = userTable.filter(
  where("id").notIn(userIds)
).runSyncAndGet
```

### Pagination

```scala
// Simple pagination
val page1 = userTable.page(start = 0, pageSize = 10).runSyncAndGet
val page2 = userTable.page(start = 10, pageSize = 10).runSyncAndGet

// For large result sets (>10,000 rows), use PagedView
val pagedUsers = userTable.toPaged(pageSize = 1000)
pagedUsers.toIterator.foreach { user =>
  println(s"Processing user: ${user.string("name")}")
  // Only 1000 rows in memory at a time
}
```

### Mapping Results

```scala
// Extract just names (returns Seq[String])
val names = userTable.map(_.string("name")).runSyncAndGet
println(s"User names: ${names.mkString(", ")}")

// Count active users
val activeCount = userTable.count(where(ps"active = ${true}")).runSyncAndGet
println(s"Active users: $activeCount")

// Get max age
val maxAge = userTable.max("age").runSyncAndGet
println(s"Oldest user age: $maxAge")
```

## Step 8: Async Execution (Optional)

For web services and high-concurrency applications, use `AsyncRunContext` for non-blocking execution:

```scala
import sss.db._
import scala.concurrent.{Future, ExecutionContext}
import scala.concurrent.ExecutionContext.Implicits.global

object AsyncExample extends App {
  implicit val async = new AsyncRunContext(global)
  val db = Db("database")
  val userTable = db.table("users")

  // Returns Future[Row] instead of Try[Row]
  val futureUser: Future[Row] = userTable.persist(Map(
    "name" -> "Dave",
    "email" -> "dave@example.com",
    "age" -> 35
  )).run  // Note: .run (not .runSync)

  futureUser.map { user =>
    println(s"✓ Created user: ${user.string("name")}")
  }.recover {
    case e: DbException =>
      println(s"✗ Error: ${e.getMessage}")
  }

  // In a real application, you'd integrate this with your web framework
  // (Play, Akka HTTP, http4s, etc.)

  Thread.sleep(1000)  // Wait for async operation (don't do this in production!)
  db.shutdown.runSyncAndGet
}
```

**When to use async:**
- Web services (Play, Akka HTTP, http4s)
- High-concurrency applications (>100 req/sec)
- When you need efficient thread utilization

**When to use sync:**
- CLI tools
- Batch jobs
- Simple scripts
- Lower concurrency (<10 req/sec)

## Complete Example

Here's a complete example putting it all together:

```scala
package example

import sss.db._
import scala.concurrent.ExecutionContext.Implicits.global
import scala.util.{Success, Failure}
import java.util.Date

object CompleteExample extends App {

  // Setup
  implicit val sync = new SyncRunContext(global)
  val db = Db("database")
  val userTable = db.table("users")
  val postTable = db.table("posts")

  println("=== Creating users and posts ===\n")

  // Transaction: Create multiple users with posts
  val result = (for {
    // Create first user
    alice <- userTable.persist(Map(
      "name" -> "Alice",
      "email" -> "alice@example.com",
      "age" -> 30,
      "active" -> true,
      "created_at" -> new Date().getTime
    ))

    // Create post for Alice
    alicePost <- postTable.persist(Map(
      "user_id" -> alice.id,
      "title" -> "Introduction to sss.db",
      "content" -> "sss.db makes database access simple!",
      "published" -> true
    ))

    // Create second user
    bob <- userTable.persist(Map(
      "name" -> "Bob",
      "email" -> "bob@example.com",
      "age" -> 25,
      "active" -> true,
      "created_at" -> new Date().getTime
    ))

    // Create post for Bob
    bobPost <- postTable.persist(Map(
      "user_id" -> bob.id,
      "title" -> "Why I Love Type Safety",
      "content" -> "Compile-time guarantees prevent runtime errors!",
      "published" -> false
    ))

  } yield (alice, bob, alicePost, bobPost)).runSync

  result match {
    case Success((alice, bob, alicePost, bobPost)) =>
      println(s"✓ Created user: ${alice.string("name")} (id: ${alice.id})")
      println(s"  └─ Post: '${alicePost.string("title")}' (id: ${alicePost.id})")
      println(s"✓ Created user: ${bob.string("name")} (id: ${bob.id})")
      println(s"  └─ Post: '${bobPost.string("title")}' (id: ${bobPost.id})")
      println()

      // Query all users
      println("=== All users ===\n")
      val allUsers = userTable.findAll().runSyncAndGet
      allUsers.foreach { user =>
        println(s"- ${user.string("name")} (${user.int("age")} years old)")
      }
      println()

      // Query published posts
      println("=== Published posts ===\n")
      val publishedPosts = postTable.filter(
        where(ps"published = ${true}")
      ).runSyncAndGet
      publishedPosts.foreach { post =>
        println(s"- '${post.string("title")}' by user ${post.long("user_id")}")
      }

    case Failure(e) =>
      println(s"✗ Transaction failed: ${e.getMessage}")
      e.printStackTrace()
  }

  // Cleanup
  db.shutdown.runSyncAndGet
  println("\n✓ Database connection closed")
}
```

## Common Pitfalls

### 1. Forgetting to Call `.runSync` or `.run`

```scala
// ❌ Wrong: Creates FutureTx but doesn't execute it
val user = userTable.persist(Map("name" -> "Alice"))

// ✅ Correct: Executes the operation
val user = userTable.persist(Map("name" -> "Alice")).runSyncAndGet
```

### 2. Not Handling Failures

```scala
// ❌ Wrong: Can throw unexpected exceptions
val user = userTable.persist(Map("name" -> "Alice")).runSyncAndGet

// ✅ Correct: Handle both success and failure
userTable.persist(Map("name" -> "Alice")).runSync match {
  case Success(user) => println(s"Created: ${user.id}")
  case Failure(e) => logger.error("Insert failed", e)
}
```

### 3. Extracting Blobs Outside Transactions

```scala
// ❌ Wrong: Blob might not be available
val row = table.find(where(ps"id = ${id}")).runSyncAndGet
val data = row.get.blobByteArray("document")  // May fail!

// ✅ Correct: Extract inside transaction
val data = (for {
  row <- table.find(where(ps"id = ${id}"))
  data = row.get.blobByteArray("document")  // Inside FutureTx
} yield data).runSyncAndGet
```

### 4. Creating N+1 Queries

```scala
// ❌ Wrong: Creates 1 + N queries
val users = userTable.findAll().runSyncAndGet
users.foreach { user =>
  val posts = postTable.find(where(ps"user_id = ${user.id}")).runSyncAndGet
  // This creates one query per user!
}

// ✅ Correct: Use batching
val users = userTable.findAll().runSyncAndGet
val userIds = users.map(_.id)
val posts = postTable.filter(where("user_id").in(userIds)).runSyncAndGet
// Only 2 queries total
```
